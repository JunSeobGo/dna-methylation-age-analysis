# R 실행환경 재현 기준

## 목적

잠금 모델을 생성한 환경과 다른 패키지 버전에서 모델을 읽거나 다시 학습해 결과가 달라지는 일을 막습니다. 현행 파이프라인의 최소 실행환경은 `config/r_environment.csv`에서 기계 판독 가능한 형태로 관리합니다.

## 현재 고정 환경

| 구성요소 | 버전 | 정책 | 적용 범위 |
| --- | ---: | --- | --- |
| R | 4.3.3 | 정확히 일치 | 현행 번호형 파이프라인 |
| glmnet | 5.0 | 정확히 일치 | 학습, 잠금 모델 역직렬화와 예측 |

`glmnet 5.0`은 `outputs/age_density_candidate_lock_manifest.csv`에 기록된 실제 후보 모델 생성 버전입니다. 해당 파일은 실행 산출물이므로 Git에서 제외되지만 모델 MD5와 함께 로컬 감사 근거로 보존합니다.

## 실행 전 점검

PowerShell에서 다음 명령을 실행합니다. 원천 데이터나 모델 성능 결과를 읽지 않습니다.

```powershell
& "C:\Program Files\R\R-4.3.3\bin\Rscript.exe" scripts/r/0_check_r_environment.R
```

R과 필수 패키지의 설치 버전이 명세와 모두 일치해야 `PASS`가 됩니다. 버전이 다르면 즉시 패키지를 변경하지 말고, 잠금 모델을 만든 환경인지 먼저 확인합니다.

## 현행과 레거시 의존성 구분

- 현행 재현 파이프라인: `scripts/r/2_*`부터 외부 평가 스크립트까지이며 외부 패키지는 `glmnet`만 사용합니다.
- 메타데이터 다운로드와 행렬 스트리밍 처리는 가능한 범위에서 R 기본 패키지를 사용합니다.
- `1_data_download.R`과 `scripts/r/legacy/`는 초기 탐색 기록입니다. `GEOquery`, `readr`, `progress`, `WGCNA`, `sqldf` 등은 현행 모델 재현의 필수 의존성이 아닙니다.
- 레거시 스크립트 안의 패키지 설치 코드는 새 환경 구성 절차로 사용하지 않습니다.

## renv를 바로 도입하지 않는 이유

현재 현행 파이프라인의 외부 의존성이 하나뿐이고, 잠금 모델은 R과 `glmnet`의 정확한 버전을 이미 기록합니다. 이 상태에서 전체 사용자 라이브러리를 snapshot하면 분석과 무관한 패키지가 lockfile에 포함될 수 있습니다. 현행 의존성이 늘어나거나 별도 배포 환경을 만들 때 깨끗한 라이브러리에서 `renv.lock`을 생성합니다.

환경 정책을 변경하면 잠금 모델 재학습 필요 여부와 기존 결과 호환성을 함께 검토하고 ADR로 기록합니다.
